# CodeBadger UI requirements

- Use direct, factual copy. Text must name something, state a fact, explain behavior, or tell the user what to do.
- No slogans, taglines, motivational messages, praise, marketing heroes, or metaphors about hands, rust, laps, or muscle memory.
- Make the actual coding task the exercise heading. For example: “Declare an integer named lives initialized to 3.” Put required names, values, and accepted syntax directly below it.
- Page titles name the screen or programming topic. Do not add subtitles that repeat or embellish them.
- Preserve technical explanations, relevant hints, checker limitations, keyboard shortcuts, and factual progress feedback.
- Apply these rules to lessons in every language, scenarios, typing drills, sessions, settings, errors, empty states, and generated content prompts.
- Historical design documents under docs/superpowers describe previous versions; they do not override these requirements.
